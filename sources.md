# Optional benchmark sources

External framework inventories can illustrate available interfaces; they do not
measure user productivity, percentiles, or a universal maturity ceiling. Do not
recommend installing more skills/hooks simply to match a count.

Inspect relevant primary repositories using any available structured integration,
repository checkout or browser. Examples include anthropics/skills, openai/codex,
obra/superpowers, garrytan/gstack and research harness repositories. These are
discovery leads, not a fixed fetch order or a list that must always be exhausted.
Record the revision/retrieval date and distinguish advertised features from
observed execution. Avoid maintaining star counts or quotas in instructions.

For local installation questions, inspect the active host's registry and known
skill roots without reading or printing credentials. A filesystem cache is not
proof of enabled registration. `collect.sh` is an explicitly Claude-configuration
adapter; it does not report Codex runtime coverage. Use the host's available
plugin/skill inventory for that question.

Cache only if repeated collection warrants it and saving is in scope. Resolve
a task-local or configured cache path; retain timestamps and label stale results.
Unavailable access means unknown, not zero features. Reports should connect
observed friction to evidence and a testable smaller change, not a ranking.
